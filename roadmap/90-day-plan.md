# 90-Day Engineering Portfolio Roadmap

**Baseline date:** 2026-10-11  
**Tracking principle:** Days are numbered development sessions, not automatically elapsed calendar days.

## Outcomes

- Three standalone, production-minded showcase repositories.
- Three recorded or live demos.
- Three case studies backed by implementation evidence.
- A polished GitHub profile and a simple personal portfolio website.
- Reusable Cursor and Claude Code workflows.
- A remote freelance service and proposal package.

## Phases and milestones

| Phase | Days | Planned deliverable |
| --- | --- | --- |
| Engineering foundation | 01–07 | Profile, portfolio hub, AI workflow, repository standards, first ClientFlow vertical slice |
| ClientFlow | 08–28 | Secure SaaS client portal, tests, deployment, demo |
| RelayOps | 29–49 | Webhook automation, delivery telemetry, failure tests, demo |
| DocPilot | 50–70 | Document intelligence, model evaluation, cost monitoring, demo |
| Portfolio polish | 71–84 | Security/performance review, case studies, polished UX, portfolio website |
| Freelance readiness | 85–90 | Scoped service packages, proposal templates, final portfolio audit |

## Review cadence

Every seven development sessions, review shipped functionality, evidence, design quality, technical debt, blockers, and the next sprint. Adapt scope only when the reason and impact are documented.

## Definition of done

A daily item is complete only when acceptance criteria are met, relevant tests pass, changes are reviewed, documentation is updated where needed, and a meaningful Git commit exists. For non-code documentation tasks, validate links, factual accuracy, formatting, and repository accessibility.

Project completion requires running software and independent evidence; a plan or README is not a shipped product.
